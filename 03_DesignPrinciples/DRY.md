DRY (Don't Repeat Yourself) principle is a fundamental design principle in software development that emphasizes the importance of reducing redundancy in code. 
The core idea behind DRY is that every piece of knowledge or logic should have a single, unambiguous representation within a system.
By adhering to the DRY principle, developers can create more maintainable, efficient, and less error-prone codebases.

For example, if multiple parts of an application calculate a discount using the same formula, 
create a common calculateDiscount() method instead of repeating the formula everywhere. 
This reduces duplication and makes future changes easier and more consistent.
